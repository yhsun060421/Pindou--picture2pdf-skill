# 配色方法论

## 1. 为什么必须用标准色卡

拼豆是实物，屏幕上“差不多”的颜色买不到。所有格子最终必须落到某个**真实售卖色号**上。
本项目使用 **MARD 221**（国内拼豆最主流的色号体系），数据来自
[HansBug/pindou-color-data](https://github.com/HansBug/pindou-color-data)，MIT License。
完整 221 色在 `references/palette-mard221.json`，可审计、可替换。

## 2. 从图片到格子

- 图片先做主体提取（`preprocess.py`），得到透明底 PNG。
- 按网格尺寸（两个维度都是 5 的倍数）做面积平均：
  - RGB 先按 alpha 预乘，再做 BOX 下采样，最后反预乘，避免透明边缘发黑。
  - 平均 alpha < `--alpha-threshold`（默认 64）的格子判为背景。
  - 背景格统一使用白色（MARD H1），作为调色板的最后一项，可留空不摆。
- 背景不是“无色”，而是一个真实颜色项（白色），所以总用量始终等于格子总数。

## 3. 选色

1. 收集所有非背景格子的平均 RGB，转换到 **CIELAB**。
2. 在 Lab 空间做**加权 k-means**（权重 = 该颜色出现次数，k-means++ 初始化，多次重启取最优）。
   - 默认 `--colors 12`，可调 6–20。
   - 点太多时先按唯一色聚合，保证速度。
3. 每个聚类中心用 **CIEDE2000** 找到最近的 MARD 221 色。
4. 去重与合并：
   - 同一 MARD 色号只保留一次。
   - 两个已选色之间 CIEDE2000 < `--min-delta`（默认 6）时，合并到用量更大的那个。
   - 这样避免“看起来一样、买两包豆”的情况。
5. 回填：每个格子重新用 CIEDE2000 分配到已选标准色中最近的一个（不是直接用量化中心）。
6. 去掉 0 用量的颜色，按用量从大到小重新编号 A、B、C…；白色/背景放最后。

## 4. 颜色名

图例里的中文名（深棕、浅灰、橄榄…）是**按 HSL 自动生成的描述名**，用于阅读，
不是品牌官方名称。采购与核对以 **MARD 色号 + HEX + 数量** 为准。

## 5. 校验

- 所有色号必须存在于 `palette-mard221.json`。
- 调色板 `count` 之和必须等于 `cols × rows`。
- 每个格子必须有一个已定义的字母代号。
- 交互 PDF 页数必须为 `1 + 颜色数`。

## 6. 已知局限

- 极小细节（< 1 格）会被平均掉：提高 `--max-cells` 或 `--colors`。
- 复杂渐变会被压缩成若干色阶：这是拼豆媒介的固有限制，不是 bug。
- 白底上的白色主体可能被背景移除误删：用透明 PNG，或让预处理输出浅色非白背景。
- 色卡是屏幕口径；实物豆存在批次/光线色差，报告里会提示以实物为准。

## 7. 换用其他品牌

`palette-mard221.json` 的结构是 `{code, hex, rgb, group}`。替换为其他品牌时保持同样结构，
并把 `MardPalette` 的路径指向新文件即可。注意遵守对应数据的许可证。
